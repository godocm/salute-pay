# Salute payment app

Next.js app for merchant payment creation, a shared executor queue and separate customer checkout links. Its source is tracked directly in the parent repository. Tempo and Solana are the primary integration targets; Ethereum, Base, Arbitrum, BNB Chain, Robinhood Chain and TRON have dedicated configurations. Eight public testnet deployments are verified and activated; a new deployment remains inactive until verification.

Use Node 24. From the parent repository, run `npm run build` to compile contracts and export the current ABIs, then `npm run dev` to serve the app on loopback port 5173. This directory also supports `npm run dev` and `npm run build` directly. Public routes are `/` (homepage), `/chains`, eight themed `/chains/{chain}` pages, `/about` and `/docs` (deployed addresses). Payment workspace routes are `/app`, `/executor`, `/developer` and `/pay/{slug}`. `/networks.html` forwards to `/chains`; `/pricing.html` and `/integration.html` remain public. Chain facts link primary sources, and merchant use cases are labelled examples.

Copy `.env.example` to ignored `.env.local`. Set server-only `DATABASE_URL`, `APP_ORIGIN` and `CRON_SECRET`, plus public `NEXT_PUBLIC_WALLETCONNECT_PROJECT_ID`. Run `DATABASE_URL=... npm run db:migrate` to create PostgreSQL tables. Shared links, public intent discovery and webhook settings use this database; exported signed links also support independent execution. No application key signs settlement transactions.

WalletConnect and discovered browser wallets support EVM; Wallet Standard supports Solana; the TronLink adapter supports TRON. Real external-wallet pairing needs operator configuration and compatible wallet software. A sponsored collection has no executor payout, but its sender still pays transaction costs. SPL payment-address setup requires merchant-funded rent.

Deploy this directory to Vercel as full-stack Next.js: its API is the backend, so no separate VM is necessary. The tracked main ABIs are sufficient for its build; Vercel does not need the parent Solidity/Rust tooling. Configure the authenticated watcher/webhook scheduler and a pooled PostgreSQL connection. The default `vercel.json` omits cron; an eligible paid deployment can use `vercel.pro.json` as `vercel.json` for minute scheduling. An external authenticated scheduler is another option. Internal step-by-step launch and testing instructions are in the parent `docs/DEPLOYMENT.md` and `docs/VALIDATION.md`. Historical funded deployment records are retained but are not used to activate the new app.

The pricing page and monthly quotas are implemented; subscription billing and staffed support are operational work. Grant paid plans with the operator-only `plan:set` CLI after verified billing. Test results are not an independent security audit.

Customers can pay by address without connecting a wallet to Salute. Hosted links support indexed cumulative status and webhooks; signed offline links support every activated rail without a hosted plan but do not supply trusted cumulative history. The executor queue filters by selected network, refreshes while visible, and verifies live balances when opening an order. Review collection amounts, reward and merchant destination before signing. A changed balance requires another review. Pending receipts block repeat collection; a reporting/RPC outage after confirmation preserves the successful receipt. For recovery, receipt explorer links use the actual execution chain.
